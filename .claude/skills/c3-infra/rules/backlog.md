# Product Backlog
- A message starting "New task" is a ticket: write it to repo cloudy-a-docs (main), `1___BACKLOG___/1.1.Product-Backlog/tasks/<session-id>/<max+1>.json`, before anything else. Why: single task ledger. Guard: test-backlog-metadata.sh.
- Schema: id, subject `#N ...`, description, activeForm, status, blocks, blockedBy, optional metadata.closed (YYYY-MM-DD). Why: build.js reads it. Guard: build.js.
- Every ticket carries `metadata.scope` = `{area, project, family?, repos: [...]}` with the registry CODES of git-repos-master `0_registry/projects-repos.json` (area → project → family → repo, e.g. `1`/`1.1` Cloudy, `1.2` Cloud-Me, `3.1` Macro-Central-Bank, `4.2` DeepXTech; `project "0"` = whole area; `{area:"0", project:"0"}` = root / fleet-wide) and current repo names; optional `names` for display. Codes and repos are checked against the vendored `1.1.Product-Backlog/data/registry-outline.json` (refresh: `bash tools/sync-registry-outline.sh`); an unknown code or repo fails, an old repo name resolves via renamed_from with a warning. Why: the backlog tracks every project, the dashboards group by area → project. Guard: test-backlog-metadata.sh (required on every id above #1306).
- After the write run `node build.js` in the Product-Backlog dir, then `bash 4___ASSETS___/4.1.Bin/test-backlog-metadata.sh` (repo root of cloudy-a-docs), then commit and push main. Why: the dashboards are generated. Guard: that test.
- New tickets go to the bottom unless the owner says prioritise; push every status change. Why: owner ordering, no stale state. Guard: none.
- Close with DONE evidence (commit, CI run id) and a line "CHECK ON THE PHONE (pending)" for any Android change; never claim the phone check passed unless the owner confirmed. Why: green CI is not device proof. Guard: none.
- BANNED: TaskCreate / TaskUpdate (and TaskGet/TaskList) for backlog tickets. They truncate the session store and have deleted tickets and closed them without evidence. A ticket is only ever the file `tasks/<session-id>/<id>.json` in cloudy-a-docs: read it, edit it, never delete or blank it (set `status` instead). Why: #1585 near-corruption of the backlog. Guard: hook ticket-guard (blocks TaskCreate/TaskUpdate and any Write/Edit/Bash that deletes or blanks a ticket JSON; settings deny list too).
- Sessions never miss the backlog: hook backlog-session-start injects the open-ticket index (id | status | subject) at session start; hook backlog-stop-push auto-commits and pushes `1___BACKLOG___/` of cloudy-a-docs at Stop (refuses to commit a deleted or blanked ticket). Override the checkout path with C3_BACKLOG_REPO. Why: no ticket left uncommitted or unseen. Guard: hooks/tests/run.sh.
