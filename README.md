# repo_master

The index of every repository this account owns. <!-- repos-count:begin -->`repos.json` registers 71 of them, grouped (the GitHub snapshot in the table below holds 74)<!-- repos-count:end -->, with a
`clone.sh` that pulls down whichever ones you want on this machine. This repo is

The repo is an Obsidian vault (`.obsidian/`, plugins in [`.obsidian/plugins/README.md`](.obsidian/plugins/README.md)).

```
./clone.sh                        # what exists here, what does not
./clone.sh cloudy-u-desktop cloud-me-notes # clone those two
./clone.sh --group d_lecole       # clone a whole group
./clone.sh --all                  # everything
```

No project code lives here. `repos.json` is the registry and `clone.sh` reads
it and nothing else; the group directories hold committed relative symlinks out
to the clones. A link that dangles is a repo you have not cloned yet — that is
the index working.

## Clone depth

`clone.sh` clones with `--depth 1 --shallow-submodules` by default: only the latest commit, so a clone is fast and takes little disk. Each repo has exactly ONE clone (in `$CLOUD_GIT_BASE`); the links point at it, so never keep a second full copy next to it.

```
./clone.sh <name>...                 # shallow, depth 1 (default)
./clone.sh --full <name>...          # full history (same as CLONE_DEPTH=0)
CLONE_DEPTH=50 ./clone.sh <name>...  # a deeper shallow clone
git -C <clone> fetch --unshallow     # later, turn an existing clone into full history
git -C <clone> submodule update --init --depth 1   # submodules stay shallow too
```

`cloud-master` is the same idea narrowed to the cloud project. See
[`a0_docs/README.md`](a0_docs/README.md) for how the two relate, why this is
not submodules, and what each directory is for.

## Git attributes (`.gitattributes_ours`)
This repo is plain metadata, so it carries no in-tree `.gitattributes`: sync clients such as GitSync (Android) treat any attributes/filters as a premium feature. The rules live in `.gitattributes_ours` (source: `0_git/src/gitattributes`) and are applied locally by `9_others/build.sh`, which sets `git config --local core.attributesFile "$PWD/.gitattributes_ours"`. On a fresh clone, run that one command (or `9_others/build.sh`) to get LF normalisation, union-merge logs and binary handling.
