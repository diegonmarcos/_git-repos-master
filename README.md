Repo folders: [`repo-folders-tree.json`](repo-folders-tree.json) (same hierarchy plus each public repo's folders to depth 3; private repos show name and URL only), rendered by `node gen-repo-folders-tree.js` into [`repo-folders-tree.html`](repo-folders-tree.html) and [`repo-folders-tree.md`](repo-folders-tree.md); the generator writes them into `1_repo-folders-tree/` with these root paths as symlinks.

No project code lives here. `repos.json` is the registry and `clone.sh` reads
it and nothing else; the numbered folders hold committed relative symlinks out
to the clones (`<farm>/<name>` -> `../` per level + name). A link that dangles
is a repo you have not cloned yet: that is the index working.

## Clone depth

`clone.sh` clones with `--depth 1 --shallow-submodules` by default: only the latest commit, so a clone is fast and takes little disk. Each repo has exactly ONE clone (in `$CLOUD_GIT_BASE`); the links point at it, so never keep a second full copy next to it.

```
./clone.sh <name>...                 # shallow, depth 1 (default)
./clone.sh --full <name>...          # full history (same as CLONE_DEPTH=0)
CLONE_DEPTH=50 ./clone.sh <name>...  # a deeper shallow clone
git -C <clone> fetch --unshallow     # later, turn an existing clone into full history
git -C <clone> submodule update --init --depth 1   # submodules stay shallow too
```

`cloud-master` is the same idea narrowed to the cloud project. See
[`a0_docs/README.md`](a0_docs/README.md) for how the two relate, why this is
not submodules, and what each directory is for.

## Git attributes (`.gitattributes_ours`)
This repo is plain metadata, so it carries no in-tree `.gitattributes`: sync clients such as GitSync (Android) treat any attributes/filters as a premium feature. The rules live in `.gitattributes_ours` (source: `_dotfiles/git/src/gitattributes`) and are applied locally by `9_others/build.sh`, which sets `git config --local core.attributesFile "$PWD/.gitattributes_ours"`. On a fresh clone, run that one command (or `9_others/build.sh`) to get LF normalisation, union-merge logs and binary handling.
